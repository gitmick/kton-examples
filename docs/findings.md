# kton-examples tutorial review

Findings from a full read-through of the tutorial: [docs/index.html](docs/index.html) plus the
14 example READMEs it links to. Reviewed at commit `1740362`.

Each finding gets a stable ID (F-001, F-002, …) so it can be referenced in discussion without
re-describing it. Location format:
- Landing page: `docs/index.html:<line>` + a short quoted excerpt (so it's still findable after edits).
- Example READMEs: `examples/NN-name/README.md#<heading-slug>` (GitHub auto-anchors headings).

Severity: `blocker` (wrong/misleading), `minor` (typo, awkward wording), `nit` (style/polish), `withdrawn` (the finding itself was wrong; the row is kept so the ID is never silently reused and the refutation stays on the record), `fixed` (addressed in the tree; the row records what was actually done).


**Blockers closed 2026-09-15.** All seven. Six of them were one defect wearing different clothes: a
prerequisite that lived only in `run.sh`, so the README's own commands could not run as printed - the
worst kind of defect in a repository whose product IS the tutorial. Each fix was checked the only way
that means anything here: by running the printed commands verbatim in an empty directory. F-020 was
the odd one out and the largest, a whole missing walkthrough for example 05.

While closing them, six README code blocks were still teaching `awk '/indexed foton/{print $3}'` and
`grep -oE 'keyid=...'` - the exact pattern that broke example 12 when `plankton verify` grew a line
(see the 2026-09-11 commit). Those now use `--print-id` and `nekton keyid`.

**Wording pass closed 2026-09-03.** All 15 rows that were still open, plus the open halves of
F-018, F-037 and F-038, are fixed and marked `fixed` with what was actually written. One row is
deliberately left as it stands: **F-010** asked to drop example 02's "acts" framing. Its concrete
complaint - two 1-2-3 schemes that looked aligned and were not - was fixed long ago; what remains is
a matter of authorial voice, and renaming someone's structural metaphor is not a review finding.

**Re-checked 2026-09-01.** Every `minor`/`nit` row was verified against the tree rather than assumed
still open. 11 had already been fixed and are now marked `fixed`, each row carrying where to see it;
4 are partly done and say what landed and what did not; 15 are unchanged and say so. A row that has
been re-checked names the date, so nobody re-verifies the same thing twice. One caveat worth stating
plainly: the B5 rewrite in `examples/04-claim/README.md` on the same day made **F-015** and **F-024**
slightly worse, adding two further unglossed uses of "opaque IRI" and "the kernel" while fixing the
predicate.
